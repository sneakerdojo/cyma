● RESEARCH BRIEF / HARNESS ARCHITECTURE

Model-Agnostic Multi-Agent Harness

DeepSeek Harness, GPT-6 Astra, and the gateway pattern that lets a tmux-driven agent ecosystem swap its underlying model as the landscape shifts — read before scoping the build.

Filed 2026-09-10 Type Technical overview Feeds Harness architecture decision
Plain verdict

The architecture is sound and not novel-risk. Model-swapping and tmux-based multi-agent orchestration are each independently solved, maintained-by-others layers — compose them, don't rebuild them. DeepSeek Harness proves the right shape (model adapters as plugins) but is too early for production. GPT-6 Astra is real, shipped, and API-reachable.

The biggest risk is contractual, not technical: the subscription-to-API billing bridge is explicitly unsupported by Anthropic's Agent SDK and likely by OpenAI's consumer terms for client-facing use.

01

DeepSeek Harness (dsh)

Confirmed real — github.com/deepseek-ai/deepseek-harness, docs at deepseek-harness.github.io. An "everything-is-a-plugin" agent harness — CLI plus a local Web UI (npx @deepseek-ai/dsh web, serves 127.0.0.1:3080) — built on Cordis, a spatiotemporal composability framework.

No privileged core. Model adapters, tool registries, session logging, agent loops, sandboxes, and even the UI are all plugins mounted alongside each other; registrations auto-revoke on unload. The load-bearing detail: model adapters are plugins, not hardcoded — the correct shape for swapping the model without rewriting the harness.

Status DEV PREVIEW

Rapid iteration, breaking changes expected. Not yet a stable target for client-facing production infra.

Traction FAST

Reported in the tens-of-thousands to 200k+ stars within days; active dsh-plugin ecosystem already forming.

Worth prototyping against, not worth committing production architecture to — the plugin shape is right, the vendor-branded pre-1.0 surface is the catch.

02

"Astra" — two unrelated things

OpenAI SHIPPED

GPT-6 Astra — released Sept 3–4, 2026. Rolling out across ChatGPT plans plus the OpenAI API and AWS. OpenAI's largest training run to date, per VP Research Aidan Clark. This is almost certainly the model you meant, and it's the one that's actually API-swappable into a harness.

Google DeepMind PROTOTYPE

Project Astra — a separate, older research prototype. Closed tester access only, feeding features into Gemini Live. No public API, no GA timeline.

Sources: OpenAI, Axios, Fortune, DeepMind. This is a days-old announcement — confirm the exact API model string and pricing directly against OpenAI's platform docs before integrating; nothing gathered here nails those down.

03

Is the swappable-model, tmux-driven design sound?

The model-swap layer already exists

Don't build model-swapping into the harness — it's a solved layer, separate from orchestration entirely.

  • LiteLLM — self-hostable proxy translating 140+ providers into one OpenAI-compatible interface. Closest match to what "Claude gateway" should mean here: a provider-agnostic proxy, not something Anthropic-specific.
  • OpenRouter — hosted equivalent, unified endpoint with fallback and consolidated billing across providers.

Put the swap point here — behind one interface for self-hosted DeepSeek, Claude, and OpenAI — not inside dsh's plugin system or bespoke tmux glue.

The tmux orchestration layer already exists

This pattern isn't something to pioneer — it's already built, more than once:

  • awslabs/cli-agent-orchestrator — AWS-authored, explicitly multi-CLI (Claude Code, Kiro, Codex) coordinated in isolated tmux sessions. The closest existing match to the whole idea.
  • tmux-orchestrator, claude_code_agent_farm, and peers — isolated tmux windows per agent, git worktrees, lock-based coordination, heartbeat monitoring.

The novel part of the idea isn't tmux orchestration — it's coupling that orchestration to a swappable model layer underneath, which is a LiteLLM/OpenRouter concern, not a tmux one.

The actual risk: billing

Anthropic's Consumer Terms exempt Claude Code CLI on your own machine from the automation ban — but that exemption does not extend to production, always-on, or client-facing automation. Anthropic's Agent SDK now technically enforces this: OAuth tokens from Free/Pro/Max accounts cannot authenticate the Agent SDK at all — API keys are mandatory. Assume OpenAI's consumer terms carry the same restriction for client automation, though that wasn't independently re-verified here.

Budget API-token billing from the POC, for every hosted provider — not just at client rollout. DeepSeek Harness's self-hosted leg is the one exception; it's a reason to weight it more heavily in a client-facing product, not less.
